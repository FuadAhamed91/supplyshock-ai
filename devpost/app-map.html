SupplyShock AI

A browser app that lets a distributor break one link of its supply chain on a 3D map, see the knock-on effects, and get an AI-recommended recovery plan. Four main pieces: network data, a simulator, an AI planner that runs the simulator many times, and the 3D map + panels that show a simulation run.

One action, end to end: “Trigger port congestion”

The same simulate() run drives what you see on the map and the numbers in the panel, so they always agree.

Reference route (3 stops)

  1. src/ui/app.js → search trigger(). Builds the scenario from the selected card, calls analyzeImpact, pauses the clock and starts the ripple animation.
  2. src/sim/engine.js → search case 'HELD' and portDispatch. Where the ship gets held at anchor and how the port restocks hubs; follow hubDispatch to see orders turn late.
  3. src/sim/planner.js → search searchPlansAsync and GUARDRAIL. Every lever combination × 40 futures, then ranking with late hospital orders weighted highest.

This route is a reference; it was not toured live.

To change this, start here

Use a different business (sites, products, demand)

Edit src/data/network.js — SITES, SKUS, ROADS. Positions are map coordinates; run npm test afterwards.

Add or tune a disruption

SCENARIOS in src/data/network.js for the card; its effect lives in simulate() (search sc.type ===) in src/sim/engine.js.

Change how the AI ranks plans

OBJECTIVES and GUARDRAIL in src/sim/planner.js.

Change a 3D model

Edit the build_* function in blender/build_assets.py, then npm run assets (Blender on PATH) to regenerate public/models/supplyshock.glb.

A practice to reuse

Calibrate with a script before you polish the UI. scripts/sweep.mjs showed that a 3-day port closure only mattered if it caught an incoming ship, so the demo depended on luck; the fix (leaner hub stock, 4-day default) is recorded in devpost/checklist.md › Revisions and guarded by tests/engine.test.mjs. On any project with a model or rules engine, a tiny script that prints outcomes across inputs finds these problems faster than clicking through the UI.

Run it again

npm install → npm run dev → open http://localhost:5173. Tests: npm test.
